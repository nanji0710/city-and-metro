# 城与轨 · 独有玩法与数据管线（fork 版）

本仓库以 [VinsonFung/city-and-metro](https://github.com/VinsonFung/city-and-metro) 为基底，
在其上叠加「我们的独有物」：**54 城真实地铁线网 + 人员雇佣体系 + 突发事件体系**。
玩法框架（绘线、建站、票价、债券、任务、里程碑）全部沿用基底，不重复造。

---

## 一、和基底的关系

| 维度 | 基底 | 本仓库 |
|---|---|---|
| 地图数量 | 6 张（教程 + 广州/杭州/香港/台北/东京） | **55 张**（教程 + 54 座中国城市） |
| 年代 | 按年代分档（1950/1970/1990/2000），选择页有「年代」筛选 | **统一 2025 年**，年代筛选已删除 |
| 开局 | 白纸，从零画第一笔 | **多数城市带既有真实线网**（`initialNetwork`），玩家接手经营 |
| 客流 | 由交通小区（ZONE=4 格）的 pop/jobs 与出行模型推导 | 同左，但 pop/jobs **由真实地铁站周边的 OSM POI 密度反推** |
| 人员 | 无 | **6 角色 × 5 等级 × 14 特性**，工资日结、忠诚度、委派托管 |
| 事故 | 无（地铁是永不出故障的传送带） | **四级突发事件**，概率按「列车·分钟」，维修费按线路规模缩放 |

保留的基底能力：绘线/建站/修改/拆除四工具、2D 与 2.5D 与地下三视图、
线路示意图（NetMap）、统计面板、任务系统、里程碑、债券融资、宏观城市经济、
存档（IndexedDB + localStorage 兜底）、音效与氛围声。

## 二、数据管线

三份输入 → 两份输出。

```
tools/src/cities/<id>.json     54 城真实线网（站名/经纬度/走向/线路色）
tools/src/poi/<id>.json        每站 500 m 半径内的 OSM 兴趣点分类计数
        │
        ├── fetch-geo.mjs ──→ js/geo_<id>.js     OSM 底图（道路/水系/公园/铁路/区界/片区名）
        │                     CM.MAP_GEO["<id>"]
        │
        └── build-data.mjs ─→ js/data_cities.js  54 城的 DATA 与地图登记
                              CM.MAP_LIST
        │
sync-html.mjs ─────────────→ index.html 的 <script> 区块（geo_* → geo → data_* → maps）
```

### fetch-geo.mjs

抓 OpenStreetMap 底图，输出**直接就是引擎格式**（`CM.MAP_GEO`），不经中间 JSON ——
中间格式只会多一个两边不一致的机会。

关键决策：

1. **每城独立格距 `cellM`**
   `cellM = max(250, ceil(maxSpan × 1.18 / 128 / 10) × 10)`。
   广州 30×24 km 用 250 m（120×96 格）；北京 92×111 km 用 870 m（108×128 格）。
   固定 250 m 会让北京得到 8.5 万个交通小区，模拟与渲染都撑不住。

2. **格网必须是 `CFG.ZONE`(4) 的整数倍**
   `js/sim.js:349` 是 `ZW = CFG.W / CFG.ZONE; Z = ZW * ZH`，
   非 4 的倍数会让 `Z` 变成小数，`new Array(Z)` 直接 `RangeError: Invalid array length`。
   基底六张图全是 4 的倍数（120×96 / 112×88 / 80×80 / 104×88 / 96×88 / 48×40）。

3. **道路等级按 `cellM` 裁剪，但永不砍到只剩快速路**
   `cellM ≤ 900` 保留到 4（含支路），再大也只砍到 3（保留主干道）。
   踩过的坑：曾按 600/900 两档砍到 2，结果南京/杭州/广州/青岛/郑州/成都
   六城 `cls3=0 cls4=0`，底图上只剩几条高速。主干道在中国城市里总共几百条，
   抓它们几乎不增加开销，却是唯一能认出城市骨架的东西。

4. **大城分块抓取**
   `n = clamp(ceil(maxSpan / 22km), 1, 5)`，块间重叠 6%（避免跨块道路在接缝处被切断），
   按 `el.type + ':' + el.id` 去重。北京 108×128 格要切 5×5。

5. **块级磁盘缓存** `tools/pipeline/.geo-cache/<city>/<j>-<i>.json`
   Overpass 公网镜像随时会被限流或超时，53 城不可能一口气跑完；
   不落盘就永远从头开始。

6. **镜像可用性必须校验「真的返回了数据」**
   踩过的坑：`overpass.osm.ch` 是瑞士区域镜像，对任何中国范围查询都返回
   HTTP 200 + `{"elements": []}`。一度被当成「唯一可用镜像」置顶，
   整轮抓取产出 0 条道路的空地图。
   正确做法：`_probe-mirror.mjs` 用 `out count;` 查询并解析 `elements[0].tags.ways`，
   `ways > 0` 才算可用。当前可用：`overpass.openstreetmap.fr`（3 s）、
   `maps.mail.ru`（23 s）、`overpass-api.de`（31 s）。

7. **小城优先的抓取顺序**
   原「大城优先」假设慢的先启动整体更短。实测北京中心块（天安门一带）单块跑十几分钟，
   一旦卡住整个 worker 就堵死，后面 44 个只需一次请求的小城一个都发不出去。
   改成小城优先后一小时能落地 44 城。

### build-data.mjs

把线网 + POI 转成引擎要的 `DATA`。

推导规则（每条都是为了「不编造，只从真实数据推」）：

- **regions** ← `geo.admin` 里 level 6 的区；不足 3 个退 level 8 街道。上限 28。
- **plans**（功能配比）← 按区内 POI **总量**排序分档，不是密度。
  30 格远郊即使每格密度高也不该盖成 CBD —— 「哪里岗位多」是绝对量。
- **centers**（人口/就业中心）← 真实地铁站 POI：
  `life → pop`（8000~62000 人/km²）、`commercial + hub×1.4 → jobs`（4000~58000）、
  `r = 1.6 + score×1.6`，最多 22 个。
- **facilities** ← `hub ≥ 6` 做铁路枢纽（最多 4 个）、`commercial ≥ 8` 做商圈（最多 6 个）。
- **initialNetwork** ← 站数最多的 4 条真实线路，每条最多 14 站。
  站太多会让开局就背上一整张网的运营成本。换乘站用 `L` 站台、其余 `M`
  —— 这决定开局能开多大编组，玩家要扩编组就得先花钱扩站台。
- **cam**（开局镜头）← 全部真实地铁站的格坐标包围盒中心，
  `zoom = clamp(660 / span, 6, 30)`。
  踩过的坑：第一版用格网几何中心，洛阳开局相机停在洛河江面上，
  画面「一片蓝一片白」，看起来像渲染坏了。
- **popCurve** ← 54 城 2025 年城区常住人口估算表，向 2020/2030/2040/2060/2300 外推。

### sync-html.mjs

重建 `index.html` 的地图脚本区。依赖顺序是硬的：

1. 所有 `geo_<id>.js` —— 只往 `CM.MAP_GEO` 挂数据，无依赖
2. `geo.js` —— 定义 `CM.Geo`（`enc`/`dec`/`init`），`data_*.js` 里的 `enc` 要用它
3. 所有 `data_*.js` —— 往 `CM.MAP_LIST` push 地图
4. `maps.js` —— 读 `CM.MAP_LIST` 与 `CM.MAP_GEO` 建立 `CM.MAPS`

手写 108 行 `<script>` 必然漏、必然顺序错。

## 三、独有玩法一：人员雇佣体系（`js/staff.js`）

### 设计立场

人员不是「买了就变强」的增益道具，而是**把不可控风险换成可预期工资的交易**。

三条硬约束：

1. **工资必须进日结算**。月底一次性扣会让玩家月中看到的日净利是假的，
   而「这条线今天养了几个人」恰恰是他每天都在做的决定。
2. **人的效率不能直接乘票款**，要作用在服务属性上让客流模型自己算。
   「多派人 → 体验好 → 有人坐」是玩家能讲通的因果链；
   「多派人 → 票款变多」不是。
3. **存档必须纯数据可无损往返**。

### 六角色

| 角色 | 基线工资 | 签约费 | 作用 |
|---|---|---|---|
| 线长 `line_manager` | 2.1 | 6.0 | **事故自动处置**（但更贵更慢），满意度 +6·w |
| 行车调度 `dispatcher` | 1.5 | 2.6 | 事故率 ×(1−0.08w)，准点 +0.06w |
| 列车司机 `driver` | 1.2 | 1.3 | 事故率 ×(1−0.05w)，准点 +0.015w |
| 车辆检修 `maintainer` | 1.3 | 1.5 | 事故率 ×(1−0.15w)，维保 ×(1−0.22w)，维修费 ×(1−0.10w) |
| 站务员 `station_staff` | 1.0 | 0.9 | 满意度 +4·w |
| 客运商业 `commercial` | 1.35 | 1.9 | 票款 ×(1+0.28w) |

### 五等级

`见习 0.72 / 熟练 0.78 / 资深 0.83 / 骨干 0.87 / 专家 0.90`（效率），
工资倍率 `1.00 / 1.22 / 1.50 / 1.85 / 2.30`，签约费倍率 `1 / 1.6 / 2.4 / 3.5 / 5`。
工资涨得比效率慢 —— 高等级「贵但划算」。

### 十四特性

`老练 0.88 / 稳手 0.92 / 冒失 1.15`（事故）、`守时 +0.025 / 拖沓 −0.02`（准点）、
`会算账 0.90 / 大手大脚 1.12`（成本）、`热心 +4 / 冷淡 −3`（满意度）、
`会做生意 1.10`（票款）、`要求高 1.15 / 务实 0.90`（工资）、`踏实 0.5`（忠诚）、
`会修 0.85`（维修）。全部是乘法，可以叠。

### 效率稀释

超过 8 人时 `dilute = 1 − min(0.25, (headcount − 8) × 0.02)`。
「管不过来」不是惩罚，是提醒玩家：再多的人也需要线长去调度。

### 接入点

- `js/economy.js` 的 `Economy.prototype.day(daily, compiled, year, dt, extra)`：
  `extra.payroll` 进 `ops`，`extra.revenueMult` 乘票款，`extra.maintMult` 乘车公里维保。
- `js/economy.js` 的 `updateSatisfaction(...)`：`opts.staffSat` 作为独立因子入账。
- `js/game.js`：`staffEffects()` 按「年:月:日:在编人数」缓存，
  `monthGen()` 里刷新市场与涨薪，`serialize()`/`restore()` 存 `staff`。

### 面板

`js/pages_staff.js` 提供 `UI.prototype.page_staff`，两个 tab：
**我的团队**（在编、工资总额、事故处置效果、逐人卡片与指派线路）与
**人才市场**（7 名候选人，3 个月后过期，含等级、特性、周薪、签约费）。
顶栏新增人员按钮，带在编人数角标与「有待处置事故」红点。

## 四、独有玩法二：突发事件体系（`js/incidents.js`）

### 为什么要有

基底里地铁是一条永远不会坏的传送带，运营退化成建造。
加进第四条成本曲线（前三条是建造、运营、债券利息）：**意外**。

三条约束：

1. **概率必须跟「列车数 × 时间」挂钩**，不能跟「天」挂钩。
   按天算是拍脑袋，玩家看不出为什么昨天没事今天连炸三次。
2. **维修费必须按线路规模缩放**。
   固定 45 万在 30 站干线是毛毛雨，在 6 站起步线是灭顶之灾。
3. **有 line_manager 的线路自动处置但更贵更慢**，否则线长成纯增益道具。

### 四级事件

| 级别 | 名称 | 权重 | 基准维修 | 停运分钟 | 满意度 | 运力损失 |
|---|---|---|---|---|---|---|
| L1 | 单列车故障 | 60% | 8 万 | 10~15 | −4 | 6% |
| L2 | 区间中断 | 25% | 20 万 | 10~30 | −9 | 18% |
| L3 | 整线降速 | 12% | 45 万 | 15~45 | −16 | 34% |
| L4 | 枢纽瘫痪 | 3% | 80 万 | 20~60 | −26 | 55% |

### 触发率

`PER_TRAIN_MINUTE = 0.00002`（**不是设计文档里的 0.0001**）。
文档的 0.005%~0.02% 是按现实列车·分钟推的，放进「1 天 = 60 秒」的游戏里
会变成开局隔一天出一次事，玩家当背景噪音。
取 0.002% 后：4 列车约 8.3% / 日，24 列车约 40% / 日 —— 与 `tools/simcheck.mjs` 实测吻合。

`p = min(0.55, 1 − exp(−expected))`。封顶理由：期望超过 0.8 后事件从「意外」变「日常」，
玩家会无视日报。一天最多一次。

### 规模缩放

`sizeFactor(n) = clamp(n / 14, 0.35, 2)`（14 站是标准线，下限 0.35 保证再小的线也有点痛感）。
`repairCost = base × sizeFactor × (自动处置 ? 1.35 : 0.75)`。

自动处置更贵（×1.35）、停运更久（×1.5）；玩家亲手处置便宜（×0.75）但要占一次操作。
**这是「用钱买时间」唯一的存在理由。**

### 运力损失怎么进模型

改的是 `js/sim.js` 里算出来的**目标发车频率**，不是直接把客流扣掉：

```js
const dis = (this.disrupt && this.disrupt[rt.id]) || 0
const need = dis > 0 ? Math.max(1, need0 * (1 - dis)) : need0
```

让挤不上去的人自己改走别的路，票款自然掉 —— 这才是玩家能看懂的那条因果链。

## 六、踩过的坑（新增部分）

1. **`growth` 必须是完整对象**
   `js/maps.js` 是 `Object.assign(cfg, m.cfg)` 逐键覆盖。
   生成器只写 `growth: { popCurve }` 会把 `CFG.growth.jobsRatio` 整条抹掉，
   `js/city.js:102` 的 `U.interp(CFG.growth.jobsRatio, y)` 读到 undefined 就 `TypeError`。
   官方 `data_*.js` 一律用 `Object.assign({}, CM.CFG.growth, {...})` 也是这个原因。

2. **格网必须是 `CFG.ZONE` 的整数倍**（见上文 fetch-geo 第 2 条）。

3. **`D.airport` 必须存在**
   `js/city.js:62-70` 无条件读 `D.airport.closeYear`，缺了直接崩。

4. **`js/render.js:702` 只画 cls 2/3/4**
   `const lay = { 2: [], 3: [], 4: [] }` 后直接 `lay[gr.cls].push(w)`，
   cls 5/6/7 会被**静默丢弃**（不报错）。所以流水线必须把道路折叠到 2/3/4。

5. **`.hidden` 不是 `display: none`**
   `css/style.css:76` 的 `.hidden` 只设 `opacity: 0; pointer-events: none`，
   截图里看到的「加载页」可能是画布本身画出来的内容。

6. **不要用 `Get-Process node | Stop-Process`**
   会把开发服务器一起杀掉。

7. **`node -e` 里含正则会被 PowerShell 吃掉**
   复杂脚本写成 `.mjs` 文件再 `node xxx.mjs`。

8. **`CM.newGame` 是异步的**
   内部 `setTimeout(…, 60)` 才真正 `useMap` + `Game.create`。
   冒烟脚本必须轮询等 `CM.game` 出现，不能紧接着读 ——
   第一版就是在这里把 16 城全部误判为「game 未创建」。
